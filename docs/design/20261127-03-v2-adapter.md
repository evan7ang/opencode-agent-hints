# V2 双入口适配计划

- 日期：2026-11-27
- 基线：`@opencode/plugin@2.4.2`、`@opencode/cli@2.4.2`（提供 `opencode2` 二进制，可与 1.x 的
  `opencode` 并存）
- 现状：`0.1.0` 只支持 V1（1.18.29–1.19.x）。V1 插件在 V2 上**不会运行**，必须移植。

## 1. 已核实的 V2 API（来自 2.4.2 的 .d.ts）

```ts
// 入口：@opencode/plugin
export interface Plugin {
  readonly id: string
  readonly setup: (ctx: Context) => Promise<Cleanup | void> | Cleanup | void
}
export declare function define(plugin: Plugin): Plugin // 恒等函数，不做运行时加工

// 逐请求钩子：ctx.session.hook(name, cb)
interface SessionModelRequest {          // "model.request"
  sessionID: Session.ID; agent: Agent.ID; model: Model.Ref
  kind: "primary" | "compaction" | "title" | "generate"
  baseURL?: string
  headers: Record<string, string>        // ← 可写，hint 头注入点
}
interface SessionContext {               // "context" / "compaction" / "generate"
  sessionID; agent; model
  system: Array<SystemPart>
  messages: Array<SessionRequestMessage> // 装配完成、即将发送
  tools: Record<string, { description: string; input: JsonSchema }>
  options: SessionRequestOptions
}
interface SessionTitle { sessionID; model; system; messages; options; result?: string }
interface SessionIdle { sessionID; background: ReadonlyArray<SessionIdleBackground> } // "experimental.idle"
interface SessionRetry { sessionID; agent; model; error; attempt; decision }
interface Fork { sessionID }             // "fork"（新会话 id）

// 其它
ctx.storage.get/set/remove/scan        // 插件私有持久 KV
ctx.session.context({ sessionID })     // 历史消息
ctx.event.subscribe({ types })         // AsyncIterable<SelectedEvent>
ctx.location.directory / ctx.options   // 目录与插件选项
```

事件（`packages/schema/src/session-event.ts`，dev 分支）：
`session.execution.started|succeeded|failed|interrupted`、`session.compaction.started|ended|failed`、
`session.archived|unarchived|deleted`、`session.forked`、`session.viewed`（`{sessionID, idle}`）、
`session.step.*`、`session.retry.scheduled`。

## 2. 映射

| 需求 | V1 实现 | V2 实现 |
| --- | --- | --- |
| 注入 hint 头 | `chat.headers` | `session.hook("model.request", e => e.headers["X-Agent-Hint"] = …)` |
| 辅助请求豁免 | agent 名 ∈ {title, compaction, summary} | `e.kind !== "primary"`（类型化，不猜） |
| `msg_offset` | `messages.transform` 快照 + 自算 | `context` hook 的 `messages`（已是装配结果）；system 按 `system` 数组计 |
| 工具集签名 | `tool.definition` 批量收集 | `context` hook 的 `Object.keys(tools)`（精确，无并发交错） |
| 真实用户输入 | `chat.message` / `command.execute.before` | `session.hook("prompt")` |
| 空闲 / pause | `session.status` + `session.idle` 事件 | `session.hook("experimental.idle", {background})`：背景任务列表可直接判断“是否还有事没做完” |
| 失败 / 重试 | `message.updated` 的 error/finish 推断 | `session.hook("retry")` + `session.execution.failed` |
| 计数持久化 | 重启时从消息表重建 | `ctx.storage`（精确、单调），重建作为兜底 |
| fork 血缘 | 无来源，省略 | `fork` hook 给出新会话 id；配合 `session.get` 可尝试得到父 id（待验证字段） |
| 焦点信号 | TUI part + 回环 IPC | `session.viewed` 事件（若 TUI/app 会发布，可删掉 IPC 与 TUI part；待 e2e 确认发布方） |
| 归档/删除/退出 | 事件 + `dispose` | `session.archived|unarchived|deleted` + `setup` 返回的 cleanup |

## 3. 打包形态

按官方迁移文档的“一个包同时支持”：

```ts
// src/index.ts
import type { Plugin } from "@opencode/plugin"
import { plugin as v1 } from "./v1.js"
import { setup as v2setup } from "./v2/index.js"

const plugin = {
  id: "opencode-agent-hints",
  setup: v2setup,
  async server(input: unknown, options: unknown) {
    return v1(input as never, options as never)   // 现有 V1 hooks
  },
}
export default plugin
```

- 不直接调用 `Plugin.define`（它只是恒等函数），避免 V1 运行时 import `@opencode/plugin` 的副作用；
  类型上用 `satisfies { id: string; setup: …; server: … }` 约束。
- 依赖：`@opencode/plugin` 只在 V2 侧用 **type-only** import；若最终需要运行时值，再加
  `dependencies`。
- 配置差异：V1 `plugin: [[spec, opts]]`；V2 `plugins: [{ package, options }]`。README 两套都写。

## 4. 实施步骤

1. 安装 `@opencode/cli@2.4.2`（`opencode2`）与 `@opencode/plugin`（devDependency，仅类型）。
2. `src/v2/`：`store.ts`（复用 `hint.ts` / `cache.ts` / `control-client.ts` 与会话状态机思路）+
   `count.ts`（从 `context.messages` 直接算 wire 条数）+ `events.ts`（事件映射）。
3. `src/index.ts` 改为上面的对象形态；V1 hook 逻辑原样搬到 `src/v1.ts`。
4. 单测：V2 store 的向量（V1–V10 的 V2 版本）+ 计数。
5. e2e：新脚本 `e2e/run-v2.sh`，用 `opencode2` + `plugins: [{package: <repo>, options}]` 跑 A/C/D；
   stub 不变。
6. 文档：README 版本矩阵、实现画像加 V2 列、符合性清单标注两套证据。

## 5. 风险 / 待验证

- `context.messages` 的 `Message` 是 provider 级消息还是 AI SDK ModelMessage？决定 `msg_offset`
  的 tool 计数方式（e2e 用 stub 的 `len(body.messages)` 对账）。
- `session.viewed` 的发布方与时机（TUI？app？desktop？）。不确定就保留 IPC，仅 V2 不用。
- `fork` hook 只给新会话 id，父 id 是否可从 `session.get` 读到（`Session.Info` 字段）。
- V2 的 `model.request` 在 WebSocket 传输下是否仍逐请求触发（上游调研提到 affinity 指纹问题；
  hint 头若参与握手哈希会重开连接——上游 feature request 里已请求“volatile headers”）。
